# Решения

## 2026-10-17 — единый octoFixes

Пользователь поручил объединить свои фиксы, сделать публичный GitHub-проект и
публиковать готовые обновления в Releases. Название octoFixes выбрано пользователем.

В один мод входят оба проекта (ME 1.1.1 + Hextech 1.1.1), включая последнюю
визуальную поправку автоплея форм. Неподтверждённый Evolution-баг не включён.
Namespace модулей сохранены, но игровая точка запуска, DLL и манифест общие.
Патчи модулей ставятся отдельно с разными Harmony ID.

Сборка и проверки локальные: нужны закрытые DLL установленной игры/Workshop.
В GitHub публикуются только собственный код, документация и готовый пакет фикса.
Стабильный asset octoFixes.zip позволяет использовать releases/latest/download.
Установщик переносит старые отдельные моды в резервную копию вне mods.

Причина решения: пользователь устал вручную загружать каждый архив на Google Drive
и пересылать друзьям новую ссылку. Отныне готовые проверенные исправления выпускаются
в GitHub Releases этого проекта, а друзьям передаётся один постоянный адрес:

- Проект: https://github.com/olegsubdiv/octoFixes
- Скачать последний выпуск: https://github.com/olegsubdiv/octoFixes/releases/latest/download/octoFixes.zip
- История выпусков: https://github.com/olegsubdiv/octoFixes/releases

Порядок дальнейшей работы: исправление → проверки → новая версия/CHANGELOG →
коммит и push → publish.ps1. Для изменений только документации достаточно commit/push,
новый бинарный релиз не нужен. Уже выпущенные теги и файлы не перезаписываются.
Версия объединённого мода имеет собственную нумерацию и не обязана совпадать
с номерами двух прежних отдельных фиксов.

## 2026-10-17 — Double Vision для выбора реликвий

По просьбе пользователя добавлена узкая совместимость с RelicRewardChoices:
его CustomReward не проходит через RelicReward.OnSelect, а общий перехват
RelicCmd.Obtain в транзакции выбора Hextech подавляет во избежание двойной выдачи.
Новый патч завершает custom OnSelect и передаёт только выбранную новую реликвию
в DoubleVisionRune.DuplicateObtainedRelic, сохраняя родные исключения и синхронизацию.
Активные руны определяет родной GetActiveRunes (в том числе проверяет локального пира).
Не клонируем весь экран/набор кандидатов и не патчим все получения реликвий.
При повторной попытке живого reward-объекта бонус выдаётся не более одного раза;
сохранённые уже полученные награды не удваиваются задним числом. Для этого используется
слабый маркер в памяти без новых сетевых/сейвовых свойств.

## 2026-10-17 — Void Form при стартовом автоигрывании

Восстановить пропущенный родной BeginEndTurnSuppression Hextech вокруг каждого
авторозыгрыша формы. Используется его IDisposable/AsyncLocal механизм и существующий
перехват PlayerCmd.EndTurn: без глобального запрета завершать ход и без изменения
VoidForm.OnPlay. Сигнатура scope проверяется до отключения родных обработчиков;
при несовместимом API не включать замену автоигрывания.

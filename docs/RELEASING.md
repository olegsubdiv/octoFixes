# Публикация octoFixes

Постоянная ссылка для друзей:

https://github.com/olegsubdiv/octoFixes/releases/latest/download/octoFixes.zip

Все версии и описания изменений: https://github.com/olegsubdiv/octoFixes/releases.
Рядом с архивом публикуется `octoFixes.zip.sha256`.

## Подготовка

Нужны PowerShell 7, Git, авторизованный GitHub CLI (`gh auth login`), .NET SDK и
локально установленная игра с зависимостями, необходимыми для `build.ps1`.
Публикация выполняется локально: игровые DLL и другие проприетарные файлы игры
не загружаются в Git и не используются как артефакты GitHub Actions.

1. Внести изменения и обновить версию `X.Y.Z` в `src/octoFixes.json` и проекте
   сборки. Версия assembly должна быть `X.Y.Z.0`.
2. Подготовить описание изменений в текстовом UTF-8 файле. Можно использовать
   отслеживаемый файл в репозитории либо файл вне репозитория, например
   `$env:TEMP\octoFixes-release-notes.md`.
3. Закоммитить исходники и описание, если оно находится в репозитории.
   Переключиться на `main`, отправить коммит в `origin`.

`origin` должен указывать на `olegsubdiv/octoFixes`. Рабочее дерево должно быть
чистым, включая все неигнорируемые неотслеживаемые файлы. Каталоги сборки и
локальной диагностики должны быть исключены через `.gitignore`.

## Проверка и публикация

Из корня репозитория:

```powershell
pwsh -File .\publish.ps1 -NotesFile "$env:TEMP\octoFixes-release-notes.md" -DryRun
pwsh -File .\publish.ps1 -NotesFile "$env:TEMP\octoFixes-release-notes.md"
```

Для другой папки игры добавить `-GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'`.
`-DryRun` проверяет Git/GitHub и запускает сборку с тестами и упаковкой, но
не создаёт теги, релизы и загрузки. Обычный запуск заново собирает проект и
проверяет тесты; установка в игру при публикации не выполняется.

Скрипт проверяет совпадение локального HEAD и опубликованного `main`, версии
манифестов и assembly, соответствие DLL/манифеста внутри ZIP проверенной сборке.
Затем создаёт и отправляет тег `vX.Y.Z`, создаёт черновик релиза, загружает
`dist/octoFixes.zip` и контрольную сумму и только после этого публикует релиз
с отметкой Latest. Заметки передаются GitHub CLI через файл.

## Если публикация оборвалась

После сбоя тег и черновик могут остаться на GitHub. Скрипт их автоматически
не удаляет и не переписывает. Устранить причину сбоя и повторить ту же команду
с той же версией и тем же коммитом:

- Существующий тег допустим только для текущего HEAD.
- В существующем черновике недостающие файлы дозагружаются; уже загруженные
  скачиваются во временный каталог и сравниваются по SHA256.
- Если байты отличаются, публикация останавливается. ZIP может отличаться даже
  при тех же исходниках из-за времени упаковки. Проверить черновик вручную;
  если это именно незавершённый релиз, удалить его в GitHub и повторить команду.
  Тег для того же коммита можно оставить. Автоматической замены файлов нет.
- Уже опубликованный релиз не меняется. Для исправлений повысить версию и
  создать следующий релиз. Если публикация уже завершилась, а команда сообщила
  сетевую ошибку, сначала проверить страницу релиза.

Не перемещать и не пересоздавать теги выпущенных версий. Если существующий тег
смотрит на другой коммит, выбрать новую версию. После публикации проверить
скачивание по постоянной ссылке и при необходимости сравнить SHA256:

```powershell
Get-FileHash .\octoFixes.zip -Algorithm SHA256
```

Друзьям достаточно постоянной ссылки: закрыть игру, распаковать архив и
запустить `install.bat`. Для совместной игры использовать одинаковую версию.

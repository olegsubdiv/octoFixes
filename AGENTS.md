# Правила octoFixes

Общаться по-русски. Текущий проект объединяет MultiEnchantmentCoopFix и
HextechFormRuneCoopFix; соседний старый проект больше не является источником новых выпусков.

- Перед работой читать docs/HANDOFF.md и проверять git status/ветку.
- Новый прямой запрос имеет приоритет над старым хендофом.
- Единственный игровой мод: octoFixes, одна DLL и один манифест src/octoFixes.json.
  Старые namespace внутри кода сохранены для совместимости проверок.
- Не использовать PatchAll по всей объединённой сборке: модули устанавливают свои
  патчи отдельно и используют разные Harmony ID, чтобы откат Hextech не снимал ME.
- Сборка/проверки: build.ps1 -Zip. Не публиковать DLL игры/Workshop, декомпиляцию,
  логи, сейвы, Steam ID и diagnostics. Они нужны локально для анализа.
- После завершённого и проверенного исправления обновить version в csproj и JSON,
  CHANGELOG, собрать и выпустить GitHub Release через publish.ps1, как поручил пользователь.
  Не выпускать догадки, незавершённые исправления и непроверенную сборку.
  Изменения только документации коммитить и отправлять без нового бинарного релиза.
- Публичный репозиторий: olegsubdiv/octoFixes. Постоянное имя asset: octoFixes.zip.
  Не заменять файлы уже опубликованных версий; новый код требует новой версии.
- При установке игра закрыта. Старые моды переносить в backup вне mods,
  сохранять откат при ошибке. Не трогать пользовательские сейвы.
- Состояние и практические ограничения писать в docs/HANDOFF.md;
  принятые решения с причинами — docs/DECISIONS.md.
- Локальный каталог пока сохраняет историческое имя Sts2MultiEnchantCoopFix;
  это действующий исходный проект octoFixes, а не старый отдельный мод.
- Долгоживущее решение о распространении фиксов: локальная wiki,
  F:/Work Projects/Wiki/wiki/sts2-coop-fixes.md. Живой статус брать из HANDOFF.
